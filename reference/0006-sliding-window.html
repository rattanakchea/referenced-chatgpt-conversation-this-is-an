Sliding Window

Use two indices to maintain a range instead of recomputing every subarray or substring.

Course home

Overview

Sliding window handles questions about consecutive items: subarrays in lists or substrings in strings. It replaces repeated recomputation with a maintained state that changes as the window moves.

Pattern Types

TypeWhen to use itState examples
Fixed-sizeThe problem says exactly k items.sum, count, max seen
Variable-sizeThe window grows and shrinks to satisfy a condition.frequency map, unique count, running sum

Core Ideas

  • The window is a consecutive range with a left and right edge.
  • The state summarizes what is currently inside the window.
  • The transition updates state when one item enters and one item leaves.
  • The answer is updated after the window is valid.

Update Timing Rule

Think in three phases. First, the for loop chooses a new right edge. Second, the code updates the window state so it matches that new edge. Third, the while loop moves the left edge only if the current window needs repair or improvement.

for right, value in enumerate(items):
    # Phase 1: right moved to a new item.
    # Phase 2: include that item in the window state.
    state += value

    # Phase 3: move left only when needed.
    while window is invalid or shrinkable:
        record answer if the current window is useful
        state -= items[left]
        left += 1

    record answer if the repaired window is useful

The while condition reads the current state. The body of the while changes the state by removing from the left, so the next condition check sees a smaller window.

Mental Model: Entrance and Exit

The right pointer is the entrance. New items enter there. The left pointer is the exit. Old items leave there. The window state must match what is currently inside.

  • When right moves, add the new item or prepare to add it.
  • When left moves, remove the old item.
  • Do not remove from the right inside the shrink loop. Shrinking means the left edge moves.

Longest vs Shortest

Problem typeWhen to update answerWhy
Longest valid windowAfter shrinkingThe window is valid now, so measure it.
Shortest valid windowInside the shrink loopThe window is valid before each shrink, so measure it before removing the left item.

Two Timing Examples

Longest unique substring

Here the new character might break uniqueness. The code shrinks before adding it so the set never contains a duplicate.

while ch in window:
    window.remove(s[left])
    left += 1

window.add(ch)
best = max(best, right - left + 1)

Minimum sum at least target

Here the new number might make the sum large enough. The code must add it first, then measure and shrink while the window is valid.

total += value

while total >= target:
    best = min(best, right - left + 1)
    total -= nums[left]
    left += 1

Fixed-Size Window

def max_sum_size_k(nums, k):
    if k > len(nums):
        return None

    window = sum(nums[:k])
    best = window

    for right in range(k, len(nums)):
        window += nums[right]
        window -= nums[right - k]
        best = max(best, window)

    return best

Variable-Size Window

def min_len_at_least_target(nums, target):
    left = 0
    total = 0
    best = float("inf")

    for right, value in enumerate(nums):
        total += value

        while total >= target:
            best = min(best, right - left + 1)
            total -= nums[left]
            left += 1

    if best == float("inf"):
        return 0
    return best

Fixed-Size Checklist

  1. Return early if k is impossible.
  2. Compute the first window.
  3. Initialize best from the first window.
  4. Loop from k to the end.
  5. Add nums[right].
  6. Remove nums[right - k].
  7. Update best.

Variable-Size Checklist

  1. Initialize left, state, and answer.
  2. Expand by moving right one step at a time.
  3. Add the new right-side value to the state.
  4. While the window is invalid or shrinkable, remove nums[left] and move left.
  5. Update the answer at the point where the window has the property the problem asks for.

Invariant

After each loop step, window equals the sum of exactly k consecutive numbers ending at right.

Complexity

Time is usually O(n) because each item enters the window once and leaves the window once. Space is O(1) for numeric state, or O(k)/O(n) when the state is a set or frequency map.
