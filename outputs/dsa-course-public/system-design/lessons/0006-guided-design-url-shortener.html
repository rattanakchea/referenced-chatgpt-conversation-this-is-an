Prompt

Design a service that creates a short link for a long URL and redirects visitors from the short link to the original URL. Keep the first version focused on creation and redirection. Analytics, custom aliases, and user accounts are optional extensions.

Clarify and Estimate

  • Are short links public or private?
  • Do links expire?
  • What redirect latency matters?
  • Assume reads greatly outnumber creations and each mapping is small.
Make the read-heavy shape explicit. It will influence caching, replicas, and the redirect path.

One Deep Dive

Short-code generation must avoid collisions. A service can generate a unique identifier, encode it into a compact alphabet, and rely on a uniqueness constraint at the database boundary. If a collision occurs, retry creation. The redirect path should read the cache first, fall back to the database, populate the cache, and return a redirect.

Decision Benefit Cost
Cache redirects Lower latency and database reads. Expiration and stale mappings.
Async analytics Redirect is not blocked by event recording. Events can arrive late or be lost without durable queueing.
Database uniqueness constraint Correctness at the final boundary. Creation may retry under collisions.
