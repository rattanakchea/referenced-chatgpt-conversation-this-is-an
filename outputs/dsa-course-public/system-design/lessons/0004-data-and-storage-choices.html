Start With the Access Pattern

Ask what keys the system looks up, whether records relate to each other, how often data changes, and whether a read can tolerate a slightly old answer. The product's access pattern should lead; the database brand should follow.

Need Natural starting point Question to expose the tradeoff
Relationships and transactions Relational database Which operations must succeed together?
Simple key-based access at large scale Key-value store What query flexibility are we giving up?
Flexible document-shaped records Document store How will records evolve and be indexed?
Fast repeated reads Cache in front of storage What is acceptable staleness?

Indexes, Replicas, Partitions

An index spends storage and write work to accelerate a known lookup. A replica can improve read capacity or availability but introduces lag. A partition spreads data and load but makes cross-partition queries and transactions harder. Name the benefit and the cost together.

“We need a NoSQL database” is not a design argument. “We need predictable lookups by short code at high volume, and can avoid joins” is.
