Six Moves

1. Clarify Functional requirements, non-goals, users, and quality priorities.
2. Estimate Requests, storage, bandwidth, and dominant read/write shape.
3. Model API endpoints, entities, identifiers, and ownership of invariants.
4. Design One simple end-to-end request path and its durable state.
5. Deep dive One bottleneck, failure mode, or high-value tradeoff.
6. Summarize What the design optimizes, what it gives up, and what comes next.

Interview Sentence Stems

  • “I’ll assume ___ so I can focus on ___.”
  • “The dominant access pattern is ___, so I’ll start with ___.”
  • “This component is here to relieve ___; the cost is ___.”
  • “If that assumption changes, I would revisit ___.”
