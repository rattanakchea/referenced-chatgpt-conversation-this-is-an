System Design Reference

Reliability Patterns

Make slow, overloaded, and failed dependencies visible in the design.

Module homeRoadmapGuided practice
Pattern Question Guardrail
Timeout How long can this dependency hold a request? Bound resource usage.
Retry Is the failure transient and the operation safe? Backoff, jitter, retry limit.
Idempotency What if the client sends the same write twice? Key and stored result.
Rate limiting Who gets protected when demand exceeds capacity? Clear rejection behavior.
Backpressure What happens when consumers fall behind? Bound queues and shed work intentionally.
Observability How will we know what is failing? Metrics, logs, traces, ownership.

Reliability Review

Walk the request path and ask what happens when every dependency is slow, unavailable, duplicated, or returning malformed data. Then state whether the user sees a retry, fallback, partial result, or explicit error.
