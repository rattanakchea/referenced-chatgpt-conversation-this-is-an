Lesson 7

Variable-Size Sliding Window

Goal: grow and shrink a window until it satisfies a condition.

Previous: Fixed Window Practice Roadmap Next: Stack

Overview

A variable-size sliding window is for problems where the valid range can be short or long. The right pointer usually expands the window. The left pointer shrinks it when the window is invalid, or when you are trying to make a valid window smaller.

The main mental shift: fixed windows move in lockstep, but variable windows breathe. They expand, then shrink, while preserving a useful condition.

Core Ideas

Expand

Move right to include a new item and update state.

Shrink

Move left while the window is invalid or can be improved.

Condition

The rule that decides whether the window is good, too large, too costly, or missing something.

Answer Timing

Update the answer either before shrinking, after shrinking, or during shrinking depending on the problem.

Core Template

def variable_window(nums):
    left = 0
    state = initial_state
    answer = initial_answer

    for right, value in enumerate(nums):
        add value to state

        while window breaks the rule:
            remove nums[left] from state
            left += 1

        update answer from the valid window

    return answer

When Do We Update the Window?

Think of each for loop as choosing a new right edge. After that, the window state must describe the window ending at that right edge. The only question is whether you add the right-side item immediately, or shrink first so adding it will be safe.

for right, ch in enumerate(s):
    # The right edge moved to ch.

    # If ch would break the rule, move left first.
    while ch in window:
        window.remove(s[left])
        left += 1

    # Now it is safe for ch to enter.
    window.add(ch)

Sometimes you see the check before the add, like while ch in window. That is still the same idea, but written to avoid temporarily putting a duplicate in the set. The loop is asking: "Before I add ch, do I need to remove old characters until adding ch is safe?"

Rule of thumb: update the right-side value once per for loop. Use the while loop only to remove left-side values until the window is valid again.

The Mental Gap

The confusing part is that while is not a second scan. It is a repair loop for the same right edge. The outer loop says, "Try this new right value." The inner loop says, "Move left until this right value is allowed."

Code locationQuestion it answers
Before the whileWhat changed because right moved?
Inside the whileWhat must leave because left moved?
After the whileWhat answer can I record now that the window is valid?

Two Equivalent Styles

For unique-character windows, both styles are valid. The second style is often easier to understand at first.

Check Before Add

while ch in window:
    window.remove(s[left])
    left += 1

window.add(ch)

Add Then Repair

window.add(ch)

while duplicate exists:
    remove s[left]
    left += 1

Example 1: Longest Substring Without Repeating Characters

Medium Classic

Problem

Return the length of the longest substring with no repeated characters.

assert length_of_longest_unique("abcabcbb") == 3
assert length_of_longest_unique("bbbbb") == 1
assert length_of_longest_unique("") == 0

Key Idea

The window is valid when every character inside it is unique. If the new character already exists in the window, shrink from the left until it is removed.

def length_of_longest_unique(s):
    left = 0
    window = set()
    best = 0

    for right, ch in enumerate(s):
        while ch in window:
            window.remove(s[left])
            left += 1

        window.add(ch)
        best = max(best, right - left + 1)

    return best

Example 2: Minimum Size Subarray Sum

Medium Classic

Problem

Return the length of the shortest subarray whose sum is at least target. If none exists, return 0.

assert min_subarray_len(7, [2, 3, 1, 2, 4, 3]) == 2
assert min_subarray_len(100, [1, 2, 3]) == 0

Key Idea

Expand until the sum is large enough. Then shrink while it remains large enough, because smaller valid windows are better.

def min_subarray_len(target, nums):
    left = 0
    total = 0
    best = float("inf")

    for right, value in enumerate(nums):
        total += value

        while total >= target:
            best = min(best, right - left + 1)
            total -= nums[left]
            left += 1

    if best == float("inf"):
        return 0
    return best

Example 3: Max Consecutive Ones After Flipping K Zeros

Medium

Problem

Given a list of 0s and 1s, return the longest run of 1s possible after flipping at most k zeros.

assert longest_ones([1, 1, 0, 0, 1, 1, 1, 0], 1) == 4
assert longest_ones([0, 0, 1, 1, 1], 2) == 5

Key Idea

The window is valid when it contains at most k zeros. Track zero count as the state.

def longest_ones(nums, k):
    left = 0
    zeros = 0
    best = 0

    for right, value in enumerate(nums):
        if value == 0:
            zeros += 1

        while zeros > k:
            if nums[left] == 0:
                zeros -= 1
            left += 1

        best = max(best, right - left + 1)

    return best

Example 4: Longest Substring After Replacing K Characters

Medium+

Problem

Return the longest substring that can be turned into all one repeated character by replacing at most k characters.

assert character_replacement("ABAB", 2) == 4
assert character_replacement("AABABBA", 1) == 4

Key Idea

A window is fixable when everything except its most frequent character can be replaced: window_length - max_count <= k.

def character_replacement(s, k):
    left = 0
    counts = {}
    max_count = 0
    best = 0

    for right, ch in enumerate(s):
        counts[ch] = counts.get(ch, 0) + 1
        max_count = max(max_count, counts[ch])

        while (right - left + 1) - max_count > k:
            counts[s[left]] -= 1
            left += 1

        best = max(best, right - left + 1)

    return best
