# Mission: Software Engineering Interview Readiness

## Why

Rattanak is building practical Data Structures & Algorithms and System Design skill to prepare for software engineering interviews at big tech companies. The goal is not trivia recall or memorized architectures; it is to recognize common patterns, clarify ambiguity, explain tradeoffs clearly, and produce correct solutions under interview constraints.

## Success looks like

- Solve easy interview problems reliably in Python while explaining the invariant and complexity.
- Progress into medium problems by recognizing patterns such as two pointers, sliding window, hash maps, stacks, binary search, BFS/DFS, heaps, and dynamic programming.
- Debug edge cases without guessing, using small test cases and clear reasoning.
- Build durable recall through short lessons, retrieval practice, and repeated coding feedback.
- Break ambiguous product and infrastructure prompts into requirements, scale assumptions, APIs, architecture, bottlenecks, and tradeoffs.
- Explain how core distributed-system building blocks fit together and when their costs are justified.
- Practice communicating a complete design collaboratively instead of presenting a memorized diagram.

## Constraints

- Use Python for interview coding unless the workspace later indicates otherwise.
- Prefer concise lessons with one concrete win per session.
- Increase difficulty gradually from easy to medium.
- Prioritize patterns commonly seen in big-tech software engineering interviews.
- Keep System Design focused initially on product and infrastructure interviews; defer low-level, ML, and frontend design.

## Out of scope

- Competitive programming tricks that rarely appear in mainstream interviews.
- Advanced graph algorithms, segment trees, tries, and hard dynamic programming until the easy/medium core is stable.
- Deep infrastructure specialization and production operations beyond what is useful for the current interview-readiness goal.
