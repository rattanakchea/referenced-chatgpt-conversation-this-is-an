How to Use It

Stage Output Useful question
Clarify Functional requirements and non-goals What must users do, and what can wait?
Estimate Order-of-magnitude scale What is the dominant read, write, or storage pressure?
Model Endpoints and entities What must be addressed, stored, or retrieved?
Design One end-to-end request path Where does a request enter and where does data settle?
Deep dive One justified improvement What breaks first under the stated scale?
Summarize Tradeoffs and open questions What did we optimize, and what did we give up?

Worked Example: Paste Service

For a paste service, clarify that creating and reading pastes matter, estimate that reads may dominate writes, model POST /pastes and GET /pastes/{id}, draw a service backed by durable storage, then deep dive into caching popular reads and expiry. The framework prevents premature debate about whether the database should be SQL or NoSQL.

The framework is a sequence for spending attention. It is not a script that prevents follow-up questions.
